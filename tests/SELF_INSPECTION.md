Each check names the mechanism that satisfies it and the evidence: simulation assertions in `tests/SIMULATION_REPORT.md` (IDs like A21) or file references. "Enforced" means code refuses the wrong action. "Instructed" means only an agent prompt asks for it.

## Simulation coverage
Scenario A visits all 13 states (A64): INTAKE → … → WAITING_FOR_APPROVAL (with REVISE, STALE and re-approval) → PRODUCTION → CRITIQUE → VERIFICATION → ITERATION ×3 (one tactical, one strategic with re-approval) → BLOCKED (MAX_ITERATIONS) → user EXTEND → COMPLETE. Scenario B covers NOT_QUALIFIED blocking, no baseline, too little traffic, and an undefined guardrail.

## Known limitations (stated, not hidden)
1. **Hooks verified live, with one config recommendation.** The guard hook fired inside a live Claude Code session: a real Write to `projects/<probe>/09-copy/` before approval was blocked with the APPROVAL GATE message. Claude Code warned that Git Bash isn't installed on this machine and recommends `"shell": "powershell"` on each hook entry in `.claude/settings.json` (or installing Git for Windows). That is the user's change to make. The UserPromptSubmit approval hook can only be exercised by a real user reply. Its script was tested with Claude Code-shaped payloads.
2. **Approval must be a typed reply.** An answer given through a multiple-choice tool (AskUserQuestion) never reaches the UserPromptSubmit hook. The orchestrator protocol therefore forbids that tool for the approval gate.
3. **The shell-command guard is heuristic.** It catches the obvious ways to forge state from the shell; it is not a sandbox. The authoritative gates are the engine's checks plus the approval hash.
4. **Independence of critic, verifier and builder is instructed, not tool-enforced.** They inherit all tools because they need the browser and MCP tools. Freshness checks force them to re-run each iteration, and the engine recomputes the verdict instead of trusting it.
5. **Fixtures, not live agents.** The simulation proves the state machine, gates and hooks. The first real `/optimize <url>` run is the integration test of agent quality.
6. **Statistics are approximate.** The Lehr formula (α 0.05, power 0.8) is a planning estimate, not a test procedure.
7. **Windows PowerShell 5.1.** The hook commands call `powershell`. On macOS or Linux, install PowerShell 7 and change `powershell` to `pwsh` in `.claude/settings.json`. The scripts are PS 5.1-compatible ASCII.
